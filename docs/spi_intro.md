## SPI (Serial Peripheral Interface) – Introduction

SPI (Serial Peripheral Interface) is a **synchronous serial communication protocol** widely used in embedded systems. It enables data exchange between **one master device** and **one or more slave devices**.

The master can transmit data to a slave, receive data from a slave, or perform full-duplex communication.

---

## Typical SPI Applications

Common SPI slave devices include:
- Sensors
- EEPROM / Flash memory
- SD cards
- LCD / OLED displays
- Wireless modules (Wi-Fi, Bluetooth)

SPI is preferred in embedded systems due to its **high speed**, **simple hardware**, and **low protocol overhead**.

---

## SPI Bus Overview

An SPI bus consists of a set of dedicated signals that enable communication between a master and slave devices.

Typically, SPI uses **four main signals**:
- MISO
- MOSI
- SCK (SCLK)
- NSS (SS)

---

## SPI Signal Description

### MISO – Master In Slave Out
- **Data line**
- Transfers data **from slave to master**
- Used by:
  - Master mode → data reception
  - Slave mode → data transmission

---

### MOSI – Master Out Slave In
- **Data line**
- Transfers data **from master to slave**
- Used by:
  - Master mode → data transmission
  - Slave mode → data reception

---

### SCK / SCLK – Serial Clock
- **Clock signal** generated by the master
- Synchronizes all data transfers on MOSI and MISO lines
- SPI communication is **not possible without SCK**

📌 **Debug tip:**  
If SPI communication fails, the first signal to check is whether the master is generating the clock on the SCK line.

---

### NSS / SS – Slave Select
- **Slave control signal**
- Used by the master to select a specific slave device
- Does **not** carry data

Notes:
- Not strictly required in single-slave systems
- Essential when multiple slaves share the same SPI bus
- Each slave typically has its own NSS line

---

## SPI Communication Summary

- SPI is a **synchronous** protocol
- The master:
  - Generates the clock
  - Selects the slave
- The slave:
  - Receives the clock
  - Communicates only when selected
- Signal roles:
  - MOSI & MISO → data transfer
  - SCK → synchronization
  - NSS → slave selection

---

## Key Takeaway

SPI is a fast and efficient communication protocol based on a master-generated clock and dedicated data lines. Understanding the role of each SPI signal is fundamental before configuring or debugging SPI peripherals on STM32 or other microcontrollers.
