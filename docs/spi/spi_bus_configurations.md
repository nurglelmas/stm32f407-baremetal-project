# SPI Bus Configurations (STM32)

This document describes the different SPI bus configurations supported by STM32 microcontrollers and explains their use cases, signal behavior, and design implications.

Understanding SPI bus configurations is essential for writing correct bare-metal drivers and for designing reliable hardware–software interfaces.

---

## Overview of SPI Communication

SPI (Serial Peripheral Interface) is a **synchronous serial communication protocol** that supports communication between:

- One **master**
- One or more **slave** devices

Both the master and the slave **must support SPI hardware**.  
If a slave device does not support SPI, SPI communication is not possible.

SPI communication is based on four primary signals:

- **MOSI** – Master Out, Slave In (data)
- **MISO** – Master In, Slave Out (data)
- **SCK** – Serial Clock (generated by the master)
- **NSS / SS** – Slave Select (active LOW)

---

## Slave Select (NSS) Behavior

Before any SPI data transfer can occur, the master must **select the target slave**.

- The master pulls the slave’s **NSS (SS) pin LOW**
- Only after NSS is LOW:
  - The slave activates its SPI circuitry
  - MOSI and MISO pins exit **High-Impedance (Hi-Z)** state

If NSS remains HIGH:
- The slave ignores SPI traffic
- MISO and MOSI stay in Hi-Z state
- No data exchange occurs

⚠️ Correct NSS handling is mandatory for reliable SPI communication.

---

## SPI Bus Configurations

STM32 SPI peripherals support multiple bus configurations depending on application requirements.

---

## 1. Full-Duplex Communication (Default)

Full-duplex is the **default SPI configuration**.

### Characteristics

- Two dedicated data lines:
  - MOSI (TX from master)
  - MISO (RX to master)
- Data is transmitted and received **simultaneously**
- Communication is synchronized by the serial clock (SCK)

### Behavior

- Master sends data to the slave via MOSI
- Slave sends data back via MISO at the same time
- Shift registers of master and slave operate simultaneously

### Use Cases

- Sensors requiring command + response
- EEPROM, Flash memory
- General-purpose high-speed communication

---

## 2. Half-Duplex Communication

Half-duplex SPI uses **a single bidirectional data line**.

### Characteristics

- Only one data line is used
- MOSI (master) connected to MISO (slave)
- A series resistor (typically ~1 kΩ) is recommended
- One data direction at a time

### Direction Control

- If master is **transmitter**, slave must be **receiver**
- If master is **receiver**, slave must be **transmitter**
- Unused pin remains in **High-Impedance (Hi-Z)** state

### Advantages

- Saves GPIO pins
- Useful when pin count is limited

⚠️ Half-duplex support depends on the microcontroller.  
Always verify support in the STM32 Reference Manual.

---

## 3. Simplex Communication

Simplex SPI supports **one-way communication only**.

### Modes

- **Transmit-only**
- **Receive-only**

### Characteristics

- Only required data line is connected
- Unused data line (MISO or MOSI) is disconnected
- Configuration is similar to full-duplex
- Software ignores unused input data

### Advantages

- Frees unused SPI pins for GPIO usage
- Simplifies hardware when feedback is unnecessary

### Use Cases

- Display drivers
- One-way data streaming
- Shift registers or LED drivers

---

## Design Considerations

- SPI clock (SCK) is **always generated by the master**
- No SPI communication is possible without clock
- NSS handling directly affects slave behavior
- Bus configuration must match:
  - Hardware wiring
  - Software configuration
- Unused SPI pins can be safely repurposed as GPIOs

---

## Key Takeaways

- SPI is inherently a **synchronous protocol**
- Full-duplex is default and most common
- Half-duplex and simplex modes help optimize pin usage
- Correct NSS handling is critical
- Always verify SPI configuration support in the STM32 Reference Manual

Understanding these configurations is fundamental for building robust SPI drivers and reliable embedded systems.
